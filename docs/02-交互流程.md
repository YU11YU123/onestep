# 交互流程

## 低打扰设计规则

- 记录窗口只负责“接住”，不强迫当场分类。
- 默认只显示标题输入和附件缩略图；日期、项目和象限放在可展开区域。
- 保存后的反馈不超过短暂状态提示，不自动打开主窗口。
- 每个页面只突出一个下一动作，避免同时出现多个同等醒目的按钮。
- 用明确动词替代抽象标签，例如“安排到明天”“拆出第一步”。

## 流程 A：领导临时布置任务

1. 在当前工作软件中按 `Ctrl+Alt+Space`。
2. 小窗口在屏幕中央或光标附近出现，输入框已经获得焦点，提示“你现在在想什么？”。
3. 输入任务；需要时直接 `Ctrl+V` 粘贴截图。
4. 按 `Enter`。
5. 数据写入成功后窗口关闭，焦点返回原应用；任务进入收集箱。

若写入失败，窗口不得消失，必须保留输入并说明失败原因。

## 流程 B：整理收集箱

每条任务只要求回答最多四件事：

1. 什么时候准备做？今天、选日期、以后。
2. 最晚什么时候必须完成？没有就留空。
3. 属于哪个项目？没有就留空。
4. 是否重要、是否紧急？分别选择是或否，形成紧急不重要、重要不紧急、紧急且重要、不紧急不重要四个象限。

整理完成后任务离开收集箱。允许选择“先不整理”，避免整理本身成为阻塞。

若用户再次点击当前已选象限，则取消该象限，清空重要、紧急与计划日期，并把任务退回收集箱重新显示为“未分类”；项目、提醒、截止信息、备注和附件不丢失。

## 流程 C：不知道怎么开始

1. 打开任务，点击“帮我开始”。
2. 软件展示即将发给 DeepSeek 的内容范围。
3. 用户可选择是否加入相关项目、最近完成方式或手动选中的记忆。
4. AI 返回一个最小第一步和最多五个后续步骤。
5. 结果不合适时，用户输入具体反馈并点击“重拆”；新结果仍只是建议预览，不修改原任务。
6. 点击“上一步”返回发送范围，点击右上角关闭则不采用，点击“采用”才把建议写入任务。
7. 采用后，页面只突出第一步；任务卡提供“撤销”，可恢复采用前的步骤。
8. 后续真实版本提供可选的 5/10/15 分钟启动计时。

首版 AI 不自动改截止时间、项目、四象限或完成状态。

## 流程 D：安排明天

1. 每天设定时间出现一次温和提醒。
2. 打开后左侧显示未完成的今天任务，右侧显示明天已有任务。
3. 用户可把任务移动到明天、以后或保留今天并注明逾期。
4. 页面显示明日任务数量；超过暂定上限 7 条时提示“可能排得太满”，但不强制阻止。
5. 确认后生成明日列表，次日自动进入今天。

## 流程 E：收到提醒

通知显示任务标题、截止时间（如有）以及三个动作：

- 打开任务；
- 稍后 10 分钟；
- 标记完成。

提醒不会把任务自动标记为紧急，也不会因为用户忽略一次通知就停止展示逾期状态。

## 流程 F：误点完成后恢复

1. 打开“已完成”。
2. 找到误点的任务，点击“恢复”或任务完成按钮。
3. 任务回到完成前的列表和计划日期，已填写的项目、时间、象限、备注和附件不丢失。

## 流程 G：维护项目

1. 点击项目标题右侧加号，在侧边栏原位置输入新项目名并确认。
2. 项目名平时是普通文字；双击名称后，原位置变成输入框并全选当前文字。
3. 按 Enter、点击最右侧圆角对勾或点击页面其他位置保存；按 Esc 放弃。
4. 重命名成功后，已有任务的项目归属同步更新；空名称或重复名称不创建第二个项目。

## 主界面信息架构

左侧固定导航：收集箱、今天、未来、以后、已完成、项目。主区域展示任务列表，右侧详情面板编辑当前任务；详情可以关闭，重新点击任务时再展开。四象限是今天和项目中的一种视图，不另造一套任务数据，也不增加高/中/低优先级。收集箱里尚未判断的任务单独显示“未分类”。主界面的快捷记录只保留顶部“记下一件事”一个入口。
