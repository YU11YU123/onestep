# 下一技术阶段执行任务书：让原型数据真正保存

> 状态：等待用户明确确认界面框架后执行。当前仍处于界面迭代阶段，不得提前接 Tauri、提醒或 DeepSeek。

## 目标

在不改变已确认主要交互的前提下，为 `onestep-app/` 建立可测试的本地数据层，使任务、项目、完成恢复、时间、备注、步骤和附件元数据在关闭并重新打开后仍然存在。

## 开始前

1. 读取 `README.md`、`PROGRESS.md`、`BLOCKED.md` 和本文件。
2. 确认核心动效已经完成体验，并且用户明确说可以冻结当前界面；没有确认就继续界面迭代。
3. 重新检查应用依赖、锁文件、启动/构建命令和现有 25 项浏览器回归。
4. 先提出数据层方案和迁移边界；本阶段不需要安装 Rust、C++ Build Tools 或 WebView2。

## 范围

### 必须实现

- 任务、项目和任务步骤的本地持久化；
- 计划日期、截止时间、提醒时间保持三个不同字段；
- 四象限保存 `important` 与 `urgent` 两个维度，允许收集箱未分类为空；
- 项目新增与重命名跨重启保留，重命名同步更新任务归属；
- 完成与恢复跨重启保留，并恢复到原任务列表；
- 备注和附件元数据保存；图片复制到受控本地目录；
- 保存失败时保留用户输入并给出明确错误；
- 版本化迁移、测试数据库和可恢复备份策略。

### 本阶段不做

- Tauri 桌面壳、系统托盘、真正的全局快捷键；
- Windows 通知和定时提醒；
- DeepSeek、API Key 或个人记忆；
- 安装包、账号、云同步、手机端和遥测。

## 数据与工程约束

- UI 不直接拼 SQL；通过独立的数据访问接口读写。
- 数据库变更必须有迁移，不直接覆盖旧结构。
- 图片文件与任务保存必须有可恢复的一致性策略；数据库只保存元数据和本地路径。
- 不修改 `black-white-components/`；它只是用户的开发素材库。
- 不安装全局依赖、不修改执行策略或系统配置。
- 不用跳过测试、放宽断言或吞掉错误制造绿灯。

## 验收场景

1. 新建文字任务，关闭并重新启动，任务仍存在。
2. 粘贴图片并保存，重启后图片仍可打开。
3. 新增项目并重命名，重启后名称和任务归属一致。
4. 完成任务后重启，任务仍在已完成；恢复后回到原列表，再次重启仍正确。
5. 四种重要/紧急组合落入正确象限；未分类不进入“不紧急不重要”。
6. 三类时间分别保存和读取，不互相覆盖。
7. 人为制造一次保存或迁移失败，旧数据仍可读，用户输入不丢。
8. 现有界面回归、类型检查、代码检查和生产构建全部通过。

## 完成条件

只有上述场景都用当前代码实际验证，且 `PROGRESS.md` 写明命令、结果和未验证项，才可进入 Windows 桌面化阶段。只看到页面变化或数据库文件出现，不算完成。
